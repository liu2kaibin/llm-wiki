## 执行规则

1. **去重**：剪藏 title 与 `10-Concepts\`、`60-Log\` 已有卡片名比对，主题相近即跳过。
2. **领域归档**：LLM / Database / 存储 / AI 应用 / 工具箱，新领域建子目录；卡片格式 = frontmatter（type/domain/tags/status: seed/created/source）+ TL;DR callout + 它解决什么问题 + 工作原理 + 关系（[[双链]]）+ 常见误解 + 出处。
3. **红线（涉密）**：来源是内网（oracle.sharepoint.com 等）→ 卡片必须放 `60-Log\`，出处只写「内部资料，YYYY-MM-DD 剪藏」，绝不带内网链接。
4. **不建卡判定（先例）**：
   - 邀请码返现/拉新推广 → 不建卡（2026-09-22 @PawelHuryn 先例）
   - 规避服务限制的绕限教程 + 推荐码 → 不建卡（2026-09-24 @SUOHA_AI 先例）
   - 模型发布含实测数据 → 建模型档案到 `30-Models\`（用模型档案模板字段）
5. **并入优先于新建**：同主题新素材并入已有卡（如选型表、出处补充、系列续篇），不另开新卡。先例：向量数据库选型、Transformer 演进史、OmniVoice、必藏仓库七件套。
6. **自己的话**：禁止大段复制原文；需要用户改写处标 `【改成你的话：…】`。
7. **提交**：`git add -A && git commit && git push`（根目录 D:\AI-Work\Zcode\llm-wiki，分支 main，CI 自动部署 GitHub Pages）。绝不 `git add -f`；剪藏原件一律不删。
8. **汇报**：处理清单、卡片路径、【改成你的话】位置、内网内容是否进 60-Log。无新剪藏时只回「今晚没有新剪藏」，不做提交。
9. **CI 监视**：用 `gh run watch $(gh run list --workflow=deploy.yml --limit 1 --json databaseId --jq '.[0].databaseId') --exit-status`；偶发闪失败先查 `git log/status` 再重试（commit/push 常已成功）。

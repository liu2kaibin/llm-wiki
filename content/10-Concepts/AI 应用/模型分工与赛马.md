# 模型分工与赛马

> [!abstract] TL;DR 一句话直觉
> 【改成你的话：设计和执行用不同的模型——让擅长分析的大模型读代码写方案、提 PR，再交给编码代理执行；关键任务两模型赛马取长补短。】

## 它解决什么问题
单一模型/单一订阅既做方案又做执行，容易两头都吃额度且质量互相牵制；把「想清楚」和「做出来」拆给不同模型，各自用所长。

## 工作原理（宝玉的实践）
1. **方案阶段**：把 GitHub 地址发给 ChatGPT Pro（连上自己的 GitHub 可读私有仓库），让它基于代码分析设计、写设计文档、甚至提 PR
2. **交接**：设计文档下载到本地，交给 Codex 或 Claude Code 执行
3. **赛马（horse-racing）**：同一问题让 Fable 与 GPT-6 Pro 各出一版方案，对比取长补短
4. **成本视角**：方案阶段用 ChatGPT Pro 不占 Codex 额度

## 关系
- **相关**：[[编码代理工作流]]（规划/执行两段式的模型级落地）、[[上下文工程]]（设计文档就是传给执行代理的核心上下文）、[[输出蒸馏与模型相似度]]（赛马的前提是模型间确有差异）
- **对照**：单模型全包 vs 分工+赛马——后者多花一步交接，换来方案质量与额度管理

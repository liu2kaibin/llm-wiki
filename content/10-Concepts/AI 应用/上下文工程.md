# 上下文工程（Harness 轻量化）

> [!abstract] TL;DR 一句话直觉
> 【改成你的话：AI 编码的护栏哲学一年内走完「加约束→减约束→稳定态」：模型变强后，大段流程指令反而稀释注意力，轻 Harness 赢了重 SOP。】

## 它解决什么问题
模型能力弱时需要重型框架（Superpowers 式 SOP+TDD 流程）防止跑偏，但代价是上下文爆炸——一天烧几亿 token，效果还不如现在几句话的轻量 skill。

## 工作原理（当前稳定态实践）
- **轻量化 Harness**：Anthropic 为 Claude 5 砍掉 Claude Code 八成 system prompt；Databricks 实测同一模型不同 Harness 成本差两倍以上，Pi 每轮上下文只有别的 1/3
- **Skill 选型**：matt skills 五件套（grill-me 追问 → to-spec 写文档 → to-tickets 拆任务 → implement 执行）
- **反 AI Slop**：ponytail 卡控防御性空检查、无意义 interface、过程性注释——答不上「这逻辑该不该存在」就不许写
- **并行隔离**：git worktree 隔离多任务；subagent 原生可用，Pi 哲学是 Less is More 用 tmux 原语替代

## 关系
- **相关**：[[Agent Skill]]、[[涌现能力]]（模型变强改变工程范式的例证）
- **对比**：重框架（Superpowers、gstack 多角色 review）vs 轻原语（Pi、tmux、Herdr）

## 常见误解
- 约束永远越多越好——护栏的收益随模型能力增长递减，2026 年的重点是喂干净上下文而非堆流程
